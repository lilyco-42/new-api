# DSH web-session ownership foundation

Date: 2026-09-27
Repository: `lilyco-42/new-api`
Branch: `fix/agent-toolkit-capability-claims`

## Implemented

- Added a persistent mapping between the authenticated Lain42 user, an opaque browser-facing session ID, and an internal DSH session ID.
- Added authenticated create/list/revoke routes under `/api/agent/sessions`.
- Session creation accepts no request body. The user ID comes only from the authenticated middleware; the public and DSH identifiers are generated by the server.
- The DSH identifier and platform user ID are omitted from JSON responses.
- Lookup, listing, and revocation are scoped by the authenticated user. A cross-account identifier resolves as not found.
- Added model/controller regression tests for two-account isolation, revocation, forged body fields, and internal-ID disclosure.
- Registered the table in normal and fast database migrations.

## Verification

- `gofmt` completed on changed Go files.
- `git diff --check` passed.
- Local build and test commands were intentionally not run; GitHub Actions is the required verification path.

## Not yet proven

- DSH does not yet consume this mapping or own the production chat loop.
- No DSH session creation, prompt, event-stream, or New API model-provider bridge is wired by this change.
- No deployment or browser end-to-end validation has occurred.

## Next gate

Implement a server-only DSH adapter that resolves the opaque session ID using the authenticated user, passes only the stored DSH ID to DSH, and prevents browser-supplied `userId`, `cwd`, `workspaceId`, or upstream session IDs from reaching the DSH controller. Add contract tests for repeated turn request IDs and cross-account session access before enabling any user-facing DSH chat path.
